# 简历定制面试

先确认面试官角色与本轮考察重点，再根据候选人简历和招聘岗位生成可直接使用的面试对话，包含项目追问、具体参考答案和证据记录。没有适用于所有使用者的个人默认身份或招聘岗位。

## 安装与使用

把仓库地址交给 Codex，要求安装 skills/interview-questions。也可以克隆后在仓库目录执行：

维护脚本建议使用 Python 3.10 或更新版本；本轮在 Python 3.12 验证。

    python3 scripts/sync_skill.py
    python3 scripts/sync_skill.py --check

默认安装到 ~/.codex/skills/interview-questions，尊重 CODEX_HOME。安装或更新后，在下一轮指定简历：

    使用 $interview-questions 为这两份简历生成面试问题。

如果两项信息尚未说明，Agent先只问“你这轮主要以什么身份面试这位候选人？”，收到回答后再问“这轮最想重点了解哪些方面？可以多选，并说明首要方向。”角色可以是领导、未来同事、跨团队协作方、业务负责人或HR；重点可以是技术、真实性、学习方法、AI开发、UI产品或协作。

例如回答“直属技术负责人”，再回答“技术为主，学习方法其次”。信息齐备后会简短回显并直接生成，不增加确认步骤。第二问支持自由表达多个方向，不要求填写百分比。

同一批简历只问一次。本轮已说明的角色与重点不重复问；缺一项只问该项；两项齐备可直接使用：

    使用 $interview-questions 分析这份简历。
    我是未来同事，重点看技术实现和协作；岗位是后端工程师。
    请生成60分钟稿，带具体追问和参考答案。

岗位、JD与时长优先复用本轮资料，关键缺失时再补问。技术专项保留算法与调优深度，学习专项追真实学习过程与验证。维护skill或讨论问法时不会启动面试入口问答。

## 更新

skill 源码更新后执行同一同步命令，再运行 --check 验证源码与安装文件一致。同步会检查已有安装的来源和本地修改，完整替换此 skill，移除已经从源码删除的旧文件；不会更新其他 skill。

若安装目录被手动修改，命令会拒绝覆盖，先合并或保存这些改动。不要通过删掉来源记录来绕过冲突检查。

## 质量标准

- 项目问题来自实际简历声明，岗位场景注明岗位依据。
- 从个人贡献、真实实现、取舍、故障与验证继续追问。
- 参考答案解释合理方案、前提和误区，未知项目事实不代填。
- 前端/UI、AI 工作方式、未来职责按岗位实际比重安排。
- 核心题和备用题分开，面试时间可执行。
- 每题有回答空泛、基础清楚、深入时的追问分支和停止点，参考答案区分合格与加分。
- 专项技术深挖给出算法机制、代表实现、参数或演算、失败诊断和调优验证；Agent/RAG包含独立专题参考，不只给流程性问法。
- 完整专题题库与单场时间安排分开，用户指定专项时不受默认岗位占比压缩。
- 不以 Demo、小规模、没写某技术或单次答错直接判断经历虚假。

问题质量由实际生成结果和语义检查验证。文件结构检查不能证明技术内容正确或面试有效。
