# 本轮质量核查

日期：2026-11-09。下列首轮记录对应0.2.0；后续用户反馈与0.3.0修订见末节。

## 实际做过的验证

- 完成初版创建与安装，再根据试生成问题修订并同步更新安装。
- 本地用两份用户提供的真实简历各生成一份 60 分钟稿，每份四道项目核心题、三道备用题，包含来源页、追问分支、分级参考答案、个人贡献证据、停止点和未验证记录。
- 面试环节合计 60 分钟，项目核心题合计 22 分钟；备用题需要替换或明确增加时间，不叠加进原时长。
- 对两份稿核查了来源、岗位覆盖、技术内容、事实与设想的区分、UI 与 AI 模块、求职及双方介绍。
- HR、业务负责人、原件不可读及简历包含指令的合成样例见 role-adaptation.md。
- 真实原件、个人面试稿和提取数据不进入仓库。

## 从初版发现并修正的问题

| 发现 | 修正 |
| --- | --- |
| Agent 经历容易占据过多核心时间，压缩当前前端职责的验证 | 先映射岗位能力；保留流式前端和缓存/业务边界题，UI 场景共用，Agent 深层题放备用 |
| 追问按线性清单排列，面试官不易根据回答继续 | 增加空泛、清楚、深入三种分支与停止点 |
| 参考答案容易把成熟系统措施当成所有人的必备 | 区分合格、加分及额外声明验证；未来后端题按成长目标使用 |
| AI 话题较多，原时间不足 | 模块调整为 12 分钟，用真实任务串联工具、上下文和失败处理，其他环节相应调整保持总时长 |

## 机械检查与边界

skill 官方格式校验、仓库引用与元数据检查通过；安装同步脚本的十项测试覆盖首装、更新、移除旧文件、本地修改保护、未知来源、同内容接管、只读检查、漂移、符号链接、失败恢复和其他 skill 隔离等行为。部分测试同时覆盖多个相关行为。

这些结论来自同一 agent 的试生成和语义检查，未进行独立模型盲测，也未通过实际面试验证候选人的区分效果。结构或测试通过不代表问题准确率；后续应根据实际回答、时间消耗、难度和面试官反馈修订，并再次同步安装。

## 0.3.0：修复用户指出的技术深度不足

用户审阅实际文字稿后指出：Agent部分仍停在流程，命中率、失败、检索算法与调优不足，参考答案缺具体业内方案。首轮结构检查未发现这个实用性问题，不能继续据其宣称技术深度已满足。

本次修订：

- 增加可按需读取的agent-rag-deep-dive.md，覆盖13组算法、评测、诊断、调优和Agent执行题。
- 通用答案契约增加具体机制、代表实现、参数/演算、失败信号、成本及验证；事实未知不再成为不给技术答案的理由。
- 用户指定专项时保留完整题库，之后才安排时长；默认前端岗位比例不压缩专项深度。
- 核对模型作者资料、Elastic、Sentence Transformers、pgvector和HyDE论文；模型、参数与候选人实际配置分开。
- 增加agent-retrieval-depth合成回归场景。语义核查点包括指标分母、异尺度分数融合、候选池与重排、ANN与语义召回、过滤及假设文档证据边界。

具体校准：100个可回答问题命中80个是Hit@K=80%；单题4个相关片段、Top5命中3个时Recall@5=75%、Precision@5=60%；等权RRF中c=60，两路均排第2的2/62高于只在一路排第1的1/61。调大ef_search提高的是近似索引搜索预算，不能保证修复本就不相关的向量表示。

本轮仍为同一agent核查；新版本是否符合面试官使用习惯，继续由实际讨论和面试反馈检验，不能用结构测试替代。
