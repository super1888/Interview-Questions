# Agent 与 RAG 专项深挖

适用于技术负责人核实“独立负责 Agent / RAG / 知识库”或专题讨论。此文件校准问题和参考答案的深度，不要求候选人背完所有技术名称。先问实际实现，再按回答深入；前端岗位背景不能代替核实其额外声明。

以下数字是演算或实验起点，不是通用最优参数，也不是候选人实际数据。单场面试按其方案选择连续追问，完整题库不压缩成几道泛问。

## 1. “命中率”是什么，分母是什么

主问：“你说命中率达到某个值，统计的对象、Top K、分子和分母分别是什么？”

参考答案：

- Hit@K：在可回答问题中，前 K 个候选至少含一个相关资料的问题占比。100 个问题有 80 个命中，Hit@K 为 80%。多跳问题只命中一段，不代表证据齐全。
- Recall@K：单题前 K 个结果中相关资料数 / 标注的全部相关资料数。Precision@K 则除以前 K 个结果数。需明确资料单位是文档、切片还是事实，并定义去重与相关性。
- 例：一题标注 4 段相关资料，前 5 条命中 3 段，Recall@5=3/4=75%，Precision@5=3/5=60%，该题 Hit@5=1。
- MRR 看首个相关结果位置；nDCG 可衡量不同相关等级的排序质量。先粗召回 100 条、最后选 5 条时，应分别看候选池覆盖与最终排序。
- 无答案问题单独评估拒答、误答和错误引用；答案正确性与检索命中分别统计。

追问：“换了切分方式，切片数量与标注集合变化，你怎样保持比较公平？”可按稳定文档/事实标注重新映射，不直接拿不同切片分母比较。只统计首条命中不能称为全部相关资料召回。

## 2. 哪些算法检索，为什么互补

主问：“实际用了哪些检索路线？错误码、产品型号和口语同义问法分别靠什么命中？”

参考答案：

| 路线 | 机制与代表 | 优势与限制 |
| --- | --- | --- |
| 词法检索 | 倒排索引、BM25，按词频、逆文档频率与长度归一等评分；Elasticsearch/OpenSearch 是代表实现 | 标识符、专有名词、精确术语有用；受分词、同义词与表达差异影响 |
| 稠密检索 | Bi-Encoder 分别编码 query/document，按向量相似度找近邻；BGE、E5 是代表模型族 | 同义和语义改写有用；相近主题也可能混淆版本、数字、实体 |
| 学习稀疏 | SPLADE 或 BGE-M3 sparse 等产生词项权重，可包含学习得到的扩展 | 提供词项级信号，需相应训练与索引支持，不等于直接运行 BM25 |
| 多向量/晚交互 | ColBERT 类按 token 向量交互，例如对每个查询 token 取文档 token 最大匹配再聚合 | 细粒度匹配，存储与计算开销更高，不应要求每个项目必用 |

追问：“错误码变成普通词后还命中吗？改成完全同义表达呢？”用于检验方案边界。BM25 没命中时先看 analyzer、分词和精确字段；稠密结果错时看模型、实体/版本与语料，不能只说换向量库。

## 3. 混合检索怎样融合

主问：“两路结果怎么合并排序？BM25 分数和余弦相似度能否直接相加？”

参考答案：

- RRF（Reciprocal Rank Fusion）：score(d)=Σ w_i/(c+rank_i(d))，用名次融合；不在某路候选中的文档不给该路贡献。c 是平滑常数，不是召回数量 K。
- 举例 c=60、等权：B 在两路都排第2，分数为 2/62；A 只在一路排第1，为 1/61。因此 B 高于 A。RRF 分数不是答案正确概率。
- 另一条路线是分数归一化/校准后的加权融合；BM25 与余弦原始分数尺度不同，不能随意直接相加。RRF 容易组合不同来源，但丢弃了原始分数差距信息。
- 演示流水线：BM25 Top100 与 dense Top100 → 按稳定切片身份去重 → RRF → 40 个候选 → reranker → 约6段上下文，并服从总 token 预算。

追问：“若一路主要贡献精确标识符，一路主要贡献语义结果，你如何调权重和候选窗口？”在固定样本集上比较候选覆盖、最终排名和延迟，不把某个权重当经验真理。

## 4. 为什么还要重排

主问：“向量相似度已排序，Cross-Encoder 为什么可能更准？它能解决哪一层的问题？”

参考答案：

- Bi-Encoder 可以预先计算文档向量；Cross-Encoder 将 query 与每段候选共同输入模型，直接评分，通常更贵，适合对少量候选精排。
- 代表实现有 Sentence Transformers CrossEncoder、BGE reranker；例如 bge-reranker-v2-m3 接收 query/passage 对并输出相关分数。
- 比较重排前后在同一候选池的 nDCG/MRR、最终 Recall@5 与答案支持度，并测推理延迟。
- 重排可把候选池内相关资料推到前面，提升最终 Top5 召回；不能找回粗召回池之外的资料。长文本截断也可能把关键事实截掉。
- 将 raw score 经 sigmoid 映射到0～1，不等于已经校准为“答案正确概率”。

追问：“正确资料不在Top100，重排能救吗？在Top100但不在Top5呢？”前者应检查召回，后者才适合诊断排序与候选内容。

## 5. Embedding 选型与输入细节

主问：“为什么选这个模型？如何确认客户端、入库与查询真正按模型要求运行？”

参考答案：

- 对比中文/多语言、术语和代码、长文本、可部署成本及实际查询，采用业务标注集，而非仅看公共榜单。
- 代表例：BGE-M3 支持 dense、sparse、多向量输出，其 dense 维度为1024；multilingual-e5-large 也是1024维，但这不意味着两者向量可以混用。
- E5 此型号的检索示例要求 query: / passage: 前缀，长输入截断至512 tokens；不同型号或 instruct 版本应查其作者规范，不能给所有模型套同一前缀和上限。
- 检查实际 tokenizer、截断、pooling、归一化、相似度算子、模型版本和向量维度。模型换了，即使维度相同，也通常要重建索引。

进阶：“行业术语仍区分不好，何时微调？”先排除解析、分词、前缀、切分和过滤问题；有质量可靠的 query-positive-hard negative 后，可做对比学习的 embedding 或 reranker 微调。难负例要避免把等价正确片段误标成负例；训练和评测分离，计算维护成本。

## 6. 切分怎样影响命中与回答

主问：“块大小为什么这样设？相关条款的前提和结论分到两块，会怎样？”

参考答案：

- 固定窗口便宜，结构切分可按标题、段落、FAQ、表格或代码边界；保留标题路径、表头、单位和版本，语义切分也是可选路线，需要验证额外成本。
- 小块较聚焦但可能缺条件，大块信息完整但可能语义稀释、截断或浪费上下文。重叠可缓解边界丢失，也带来重复结果与索引体积。
- Parent-child / small-to-big：小片段检索，命中后扩展父段或相邻句窗口，再去重与控制 token。索引表示和最终给模型的上下文不必完全相同。
- 可对256/512/1024 tokens及不同重叠做实验，必须说明是字符还是token，比较同一资料/事实标注和生成效果，不把某个切片数当普适最优。

追问：“表格拆开后没表头、条款缺‘海外用户除外’，你具体怎样保留并验证？”引用保留原文版本和位置，不能让模型编造页码。

## 7. 有答案却没命中，怎样分层诊断

主问：“给你一个可复现的失败问题，怎样用数据证明故障在哪层？”

| 观察信号 | 优先检查 | 具体措施 |
| --- | --- | --- |
| 原始资料存在，解析文本没有关键事实 | OCR、表格/公式解析、索引任务状态 | 修解析、保留结构、重建相关资料索引 |
| 文本有事实，但切片缺前提或实体 | 边界、标题、长度截断、文档版本 | 结构切分、补标题/父段、小到大扩展 |
| 精确向量查询也找不到正确片段 | 查询语义、模型输入、实体/版本、过滤与语料 | 校验输入和过滤；词法/混合检索、改写、必要时换模型 |
| 精确搜索有，ANN搜索没有 | 图/聚类索引的近似损失 | 提高查询搜索预算、迭代扫描，按条件评估索引或精确搜索 |
| 候选池有，最终前几条没有 | 融合、rerank、去重、重排截断 | 调融合窗口和排序，比较同池排序指标 |
| 给模型的上下文已含完整正确事实，仍答错 | 上下文组装、冲突、提示与生成模型 | 压缩去噪、明确版本、核验事实与引用，评测生成部分 |

实际排查顺序服从观察证据，可先检查权限/过滤和任务状态等低成本原因。每次保存 query、过滤条件、各阶段候选ID/排名/分数、文档版本与上下文，不能只保存最终答案。禁止用放宽权限挽救召回。

## 8. 查询失败怎样改写与再次检索

主问：“第一次检索不足时，下一次查询具体改变什么？怎样避免只重复同一个动作？”

参考答案：

- 多轮问题独立化：将“它支持退款吗”结合已知上文中的实体重写，保留限制条件。
- 多查询：生成不同但等价的表达，分别检索后去重融合；注意实体、日期和否定约束不能漂移。
- 分解：比较两个版本时分别检索；多跳问题识别缺失哪条事实再查询，不能只有至少一个片段命中就结束。
- HyDE：生成假设文档作为检索表示，检索实际资料。假设文本可能含虚构细节，不能当证据或当最终答案引用；额外生成成本和漂移要评估。
- 已明确的错误码/编号应保留精确词法通道，不让改写抹掉标识符。

追问：“重试几次、为什么继续、何时澄清或停止？”给出预算、无新增证据判定、去重及证据充分性，不依据一个余弦阈值无限循环。

## 9. HNSW / IVFFlat 怎样调，调的是什么

主问：“你说调索引后召回提升，指语义相关资料召回，还是对精确近邻结果的覆盖？”

参考答案：

- ANN recall：与同一向量空间、同一距离和同一合法候选域的精确搜索TopK比较。精确搜索近邻召回100%，不等于业务问题一定答对。
- HNSW 用分层邻接图搜索；M影响连接数和内存，ef_construction影响建图候选和构建成本，ef_search影响查询搜索广度、延迟与近邻召回。
- IVFFlat 将向量分到lists，查询搜索部分聚类；probes提高通常扩大搜索量。其训练、聚类和数据分布也要检查。
- 比较ef_search例如40/100/200的ANN覆盖与P95，再看业务指标。若精确向量检索本身就找错，单纯调大ef_search无法修复语义表示。

进阶过滤：pgvector 的近似索引可在扫描后应用过滤；例如选择性很强的tenant条件会让返回候选不足。可评估提高搜索量、受支持版本的iterative scan、分区/部分索引，以及先过滤后对小集合精确搜索。策略取决于引擎、版本、数据分布与查询计划，不能推广为所有向量库行为。

## 10. 权限、版本和索引更新

主问：“同一份政策有多个版本，不同用户又有不同权限，检索实际怎样选资料？”

参考答案：

- 资料/切片带tenant、授权标签、产品、地区、生效时间、document version、embedding version等必要元数据，服务端从认证主体生成可信过滤条件。
- 问现行规则要选适用版本；做历史对比要保留相应版本，不能一律只取最新。
- 授权资料域贯穿检索、重排、上下文、缓存和引用；只在前端隐藏结果不够。缓存按用户/租户及有效权限等隔离和失效。
- 更新可构建新版本片段并校验完成后切换可见版本；任务用稳定ID和幂等、失败重试；删除先确保不可见，再清理索引及缓存，避免旧版本重新进入回答。

追问：“任务一半失败但状态ready会怎样？用户权限变了，旧缓存还能用吗？”状态命名本身不是一致性证明，需要数据数量、版本和失败恢复依据。

## 11. 怎样进行可复现的调优

主问：“给你当前系统和标注问题集，你会先改哪一层，怎样证明是这项改动有效？”

参考答案：

1. 固定资料、权限、问题、标注和版本，定义可回答、无答案、精确标识、语义改写、多跳、旧版冲突等分组。
2. 基线比较BM25-only、dense-only、hybrid，再看加reranker的收益，避免一次改模型、切分、索引和提示后无法归因。
3. 分阶段看候选Recall/Hit、最终nDCG/MRR、回答事实与引用；记录P50/P95、tokens、成本和失败率。
4. 有针对性改变切分、候选窗口、RRF权重/常数、rerank输入、ANN预算、查询改写。单因素用于解释贡献，再评估必要的参数交互。
5. 在独立保留集验证，线上灰度/影子请求与回滚；训练数据不能冒充测试集，不能只汇报平均值或只测容易样本。

追问：“候选召回提高，但回答正确率下降，你会看什么？”可能是噪声、重复、上下文预算、冲突或排序变差；加TopK不必然提升最终质量。

## 12. 无答案、引用与自动评测

主问：“怎样决定证据足够回答？检索分数0.8意味着80%正确吗？”

参考答案：

- 相似度、RRF分和未经校准的reranker分都不能直接视为正确概率；在有答案/无答案及难负例上校准拒答策略，看误答与拒答的权衡。
- 无可靠依据时澄清、有限重检、说明不足，或使用业务允许且有来源的其他检索；不能默默把模型记忆当知识库证据。
- 事实正确、faithfulness、引用支持度分别测。忠于一份过期资料仍可能答错；引用链接存在不代表支持该结论。
- Ragas等可帮助评估context precision/recall、faithfulness等，但部分指标使用LLM或参考答案近似判断，其定义不等同于手工标注的传统P@K/R@K；需结合人工核查及真实标注。

## 13. Agent 怎样组织检索与工具

主问：“固定RAG流水线之外，Agent实际在哪些条件下做决策，哪些边界由程序控制？”

参考答案：

- 可用状态流程：问题独立化/计划 → 选择知识库、结构化查询或其他合法工具 → 检索 → 判定缺失证据 → 有限改写/分解/再检索 → 依据真实来源回答或澄清。并非所有任务都需要动态Agent。
- 例如比较两版规则可拆成两次检索；实时账户状态应调业务接口，而非用静态文档猜测。
- 工具Schema限制形状，仍需执行层校验参数语义、认证主体、资源权限、超时、幂等、轮次、总token/成本。模型和文档都不能扩大授权。
- 保存每步工具、参数、观察、状态和退出原因，能复现一次失败；按任务成功率、额外工具次数和成本评价Agent收益。
- Checkpoint用于执行恢复；对话摘要与长期记忆有各自作用域和生命周期。记忆检索同样受授权与过期约束，摘要不能把猜测固化为事实。

追问：“工具超时后自动重试，会不会重复产生副作用？摘要丢失关键限制后怎样发现？”真实已实现措施与当前设计分开。
