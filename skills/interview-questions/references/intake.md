# 生成前的两问

用户指定简历并请求生成面试问题后，先确定面试官角色和本轮考察重点。安装/更新skill、讨论规则、评审已生成的问题不启动这套提问。

## 信息与顺序

在本轮任务中维护：简历或候选批次、面试官角色、重点及主次、招聘岗位、已有JD/时长/约束。角色是使用者的面试身份，不能从候选人职位推断；重点也不能从“领导”或“同事”自动推断。

| 已明确的信息 | 下一步 |
| --- | --- |
| 角色与重点都缺失 | 只问角色，等待实际回答 |
| 只有角色 | 只问重点，等待实际回答 |
| 只有重点 | 只问角色；回答后直接采用已知重点 |
| 角色与重点均有 | 简短回显后生成，不再询问或要求确认 |
| 用户明确让Agent决定某项 | 根据本轮岗位、简历和目标给出有理由的假定，然后继续；不把假定写成真实身份 |

问题分两步提出，不把角色、重点、岗位、时长、级别等一次堆给使用者。可以在等待时读取简历、提取声明，但必要信息齐备前不生成完整面试稿。

有提问工具时，一次只呈现当前缺失的问题并等待真实回复；没有工具时，直接在对话中提问并等待下一轮。工具默认选中、没有回答或等待超时不算选择。

## 第一问：面试官角色

“你这轮主要以什么身份面试这位候选人？”

可以提供以下选项并允许自由表达或组合：

- 直属领导／技术负责人
- 未来同事／同级工程师
- 跨团队协作方
- 业务负责人／创始人
- HR／招聘负责人

收到“领导”“同事”等自然回答可以按其视角继续，不要求用户填正式职称。真正影响出题且有歧义时才补问，不把每个词扩展成背景问卷。

## 第二问：本轮重点

“这轮最想重点了解哪些方面？可以多选，并说明哪个是首要方向。”

可提示这些方向：技术深度与工程能力、项目真实性与个人贡献、学习能力与学习方法、AI开发工具与工作流、UI/设计与产品判断、协作/责任意识与推进。

接受“技术为主，学习方法其次”等自然语言，不强制数字权重。若提问控件只能单选，使用自由文本并在题干提示方向，不让控件限制多方向回答。

角色提供视角，重点确定内容和深度。例如同级工程师重技术与协作，可以从接口边界和一次调试深挖；技术负责人重学习方法，应追陌生任务的资料、实验、纠错和验证过程。不能把选技术退化为只问框架名，也不能把领导身份机械改成管理泛问。

## 采用信息并开始生成

信息齐备后只作简短回显，例如：

“本轮按直属技术负责人的视角，技术深度为主、学习方法为辅；岗位沿用本轮已提供的要求。下面结合各份简历生成问题和参考答案。”

随后直接生成，不再问“是否确认”。岗位、近期/未来职责、级别、时长和团队背景优先取自本轮对话和JD；仅在确实缺失且会实质改变出题时再补问。公司事实未知保留待补。简历可用于了解候选经历，不能单独证明正在招聘的岗位。

## 批次与变更

- 同一轮或同一批多份简历只问一次，共用评价维度，各自根据经历深挖。
- 用户明确“下一位仍按这轮设置”时复用；明确开启新一轮、切换身份或岗位时，检查新任务还缺什么。旧任务的个人背景不能静默代替新任务的输入。
- 本轮对话里明确的角色与重点，即使不在最新一句，也可复用；不因多轮交流重复提问。
- 用户只改变重点时保留角色和岗位，调整受影响的问题；只改变角色时保留明确的重点，改变观察视角和解释方式。
- 当前请求已经同时提供角色和重点时，直接进入生成。只提供岗位、时长或候选人职位不等于两项已齐备。
- 资料不可读时说明限制并请求可读内容，不编造候选人的项目；已得到的角色与重点保留，不重新开始问。

## 交付检查

核对是否跳过了必要问题、重复问已知信息、将两步合并成一张长问卷、静默沿用历史个人默认、没等回复就生成、额外索要确认，或只改标题未改变内容。发现问题先修正。
