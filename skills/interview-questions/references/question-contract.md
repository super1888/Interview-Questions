# 问题与输出契约

## 输出层次

1. 本次招聘目标、面试官角色、时长与明确假设。
2. 每位候选人的简短经历主线、相关声明、待验证事项和优先深挖方向。
3. 按时间安排的对话，核心题与备用题明确分开。
4. 共用的岗位场景、AI 工作方式、求职、公司介绍与反问。
5. 面试记录位置与本轮尚未覆盖的能力。

多候选人可以共用开场和共性题；各自的项目题必须有不同依据、追问和参考答案，不能只换姓名。用户只要短稿时压缩展示，仍保留核心问题的判断依据。

## 核心题卡

- 编号、优先级、预计分钟数、所属环节。
- 依据：简历文件和页码/章节，加一小段准确原文；岗位题标为岗位依据。
- 要验证的能力或事实。
- 面试官原话：一项中心问题，能直接照读。
- 追问分支：回答空泛时回到一条操作和一个具体对象；基础清楚时追真实故障或取舍；深入时用条件变化检验理解。每题给出停止点。
- 参考答案：合格要点、加分项、原理、合理方案、适用前提、常见误区及验证方法。对额外声明的高要求单独标明，不迁移为整个岗位门槛。
- 本人参与证据：要求一个具体改动、故障、决策或交付过程；可以口述或画脱敏示意，不要求泄露公司资料。
- 判断：什么回答支持实施深度，什么回答仍需核实。尚未问到的点不能填成候选人缺陷。

项目事实与技术答案分开。例如“实际模型与维度：需候选人说明；参考判断：查询和文档必须采用兼容向量空间，模型选择应匹配语料与评测”。不能写“他使用某模型，所以正确答案是某模型”。

事实题只给核实依据；技术题才给技术参考答案。必要术语给一行解释，例如 Embedding 是把文本变成用于相似检索的向量，幂等是同一业务操作重复提交仍只产生一次预期效果。

## 技术答案的具体程度

面试官需要能解答和继续追问的内容。对有技术深度的项目声明，答案应说明：

- 常见方案叫什么、怎样工作，基线和替代路线分别适用什么条件。
- 实际可配置或可演算的内容，例如检索指标分子分母、融合公式、候选数量、索引搜索参数；区分示例值与候选人的实际值。
- 某种失败有哪些可观察信号，怎样区分原因，先改哪一层，哪些改动对此无效。
- 如何在固定评测集上比较收益与延迟、成本等代价，不能只说“效果更好”。

例如“使用混合检索提高命中率”不够：应解释 BM25 与语义向量的互补、候选如何用 RRF 或经校准的分数融合、重排看什么输入，以及怎样比较候选召回和最终排序。

“事实由候选人说明”不能替代技术参考答案；只报模型、算法和框架名称也不够。未知实际模型时仍应给代表方案及成立条件。技术名词不能成为唯一评分标准，能解释等价机制也可接受。

专题题库与单场执行稿分开。用户要求深入讨论时保留充分的算法、故障与调优分支，实际面试再按时长选择，不把完整题库伪装成全部能在一小时问完。

## 完整题卡示例

合成声明：“实现异步导出和任务进度通知”，岗位为前端。

- 主问：“点击导出以后刷新页面，你实现的任务如何继续显示？”
- 空泛时：“就用一条订单导出任务说明，前端保存什么 ID，刷新后调用哪个接口？”
- 清楚时：“讲一次轮询或通知重复导致的问题，你怎样定位并验证？”
- 深入时：“如果创建请求超时，怎样避免重试产生两个任务？”标记为条件变化，实际没实现就不记为历史成果。
- 合格答案：服务端持久化任务与状态、稳定任务身份、刷新查询恢复、轮询终止与清理；前端展示与服务端业务状态有明确边界。
- 加分答案：重复请求的业务幂等、乱序通知处理、权限隔离；不要求每个前端候选人独立写过任务队列。
- 参与证据：一次具体改动、复现过程与修复后的检查。
- 停止点：时间到，或回到具体任务后仍无法说明数据流，记录未验证并转下一题；不能在提示答案后把复述当独立掌握。

## 追问应有因果链

弱问题：“RAG 是什么？用了哪些框架？”

可用问题：“你写了知识库检索，请画出一篇文档入库到一次回答的链路，标出你实现的部分。”

顺着回答问：“为什么这样切分？哪个真实问题检索错过？你如何判断错误发生在哪一层？改动后用什么比较？”

条件变化：“同一文档有新旧两个版本，怎样选择适用版本？”这能验证迁移能力，但不能作为候选人当年已经实现的证据。

## 面试记录

按能力记录“未验证 / 有概念理解 / 有具体实施细节 / 能解释取舍并给出验证依据”，同时保留原话、证据和待核实点。若用户要求数字评分，先给行为锚点，缺失信息记未验证而非零分。

诚实承认没做过、记不清参数、项目规模小、方案简单，都不能单独证明造假。多个说法冲突时给解释机会，再记录具体未解决的矛盾。面试前不填最终得分、不虚构候选人回答，也不承诺面试能证明所有经历真实性。

## 交付前检查

- 依据：每个项目问题都能追溯到真实声明；数字和日期与原件一致；假设明确。
- 岗位：完整场次的核心题有能力与时间映射；明确的专项深挖服从本次专题目标，不因默认岗位占比省略算法和调优。未来职责按培养目标安排。
- 深度：有完整的真实问题定位链、算法机制和可复现的调优比较，并有个人贡献证据，不能全是流程、名词解释和“如果是你”。
- 答案：技术正确、具体到方案机制与实例，多种合理方案有边界；指标、参数和故障处置可继续追问；事实未知不填实际值；合格与加分分开。
- UI 与 AI：相关岗位有界面判断；AI 题要求实际任务、输入、产物和验证，不只列工具。
- 差异：每人至少有两条来自本人经历的主线；面试官角色改变后问题和答案深度确实改变。
- 时间：核心题与共用环节合计不超过约定时长；备用题单列，追问不默认逐项问完。
- 可读：主问能直接照读，有空泛/清楚/深入的追问分支与停止点，术语有简短解释，面试官能据答案继续问。
- 边界：未问到、没写、没做过、想法不错与已经做过分别记录；没有根据缺失信息提前下结论。

若发现问题，先修改再交付。结构检查只能证明文件和字段有效，不能替代对依据、技术正确性和可问性的语义检查。
