# 按声明选择技术追问

此文件提供判断依据，不是逐题必考的知识清单。只读取和使用当前候选人的相关部分。实际方案优先：先确认做过什么，再评价为什么适合当时约束。

## 前端、UI 与异步任务

### 长任务、上传、轮询

从一个真实任务走完整链路，问状态来源、稳定任务 ID、并发限制、取消、单项失败与重试、页面刷新恢复、乱序响应和组件销毁。

参考要点：上传与业务执行可有不同状态机；服务端持久化状态是业务依据；超时不等于未执行；防重复点击不能替代服务端幂等。刷新后查询已有任务，避免重新提交。轮询要有终止条件、适当间隔和清理；任务被隐藏与取消执行要区分。AI 或支付类任务还需明确重复计费边界。

### SSE、会话与缓存

网络读取块不是完整 SSE 事件，也可能拆开 UTF-8 字符。需要流式解码和事件缓冲，处理换行与多个 data 行。异步更新绑定会话、消息和请求身份；切换会话时旧请求不能污染当前视图。前端断开后，后端应按产品语义传递取消。区分正常结束、用户停止、断线和服务端失败，保留部分结果时说明持久化策略。

服务端状态缓存与本地交互状态应有明确边界，缓存键和清理要考虑用户、会话、筛选条件。问一个实际缓存失效问题，比背状态库 API 更有价值。

### 复杂界面、文件与性能

从候选人写出的时间轴、列表返回定位、多实例组件、表单草稿、Canvas 或 PDF 细节入手。问可复现问题、根因、改动和验证。

参考要点：实例隔离、事件清理、状态生命周期和并发响应；前端草稿撤销不等于服务端回滚，并发编辑需要版本或冲突处理。PDF.js 负责解析和渲染，生成方案需解释 jsPDF、Canvas、文本与分页的实际分工。截图型 PDF 要考虑清晰度、体积、文本选择和内存，大量文件处理要限制解压大小、数量和并发。

性能数据要问指标、设备/网络/缓存/数据条件、样本与归因。构建产物体积、压缩传输量、首屏资源量不同；LCP、加载完成和可交互不能混称。先定位瓶颈，再讲优化。不要把业务链路全部收益归为一个前端措施。

## RAG、Agent 与知识库

面向技术负责人核实独立实现或用户要求深入时，读取 [Agent 与 RAG 专项深挖](agent-rag-deep-dive.md)。该参考包含命中/召回/排序指标、BM25 与稠密/学习稀疏/多向量路线、RRF、重排、模型与切分、失败诊断、查询改写、HNSW 与 IVFFlat、权限过滤、索引版本、评测调优及 Agent 执行。

先确认候选人的实际方案，再沿有关算法继续；未写模型、维度和存储表示未知，不能根据 PostgreSQL 或框架名猜测实现。HR 等非技术轮按角色简化表达，保留贡献、真实故障与验收依据。

## 服务端与全栈成长

问候选人实际参与的一条接口：身份从哪里来、参数如何校验、资源归属在哪检查、数据如何写入、失败与重试怎么处理。前端岗位的未来成长题可用简单资源接口，避免直接要求复杂分布式系统。

服务端以认证主体判断资源归属，不能信任前端传入 userId。异步任务需要稳定身份、可恢复的持久化状态、有限重试和幂等；文档更新要考虑新旧索引版本的可见性与删除失效。并发提交、请求超时与消息重复都应解释业务结果。

支付或金额声明可问十进制/最小单位表示、舍入、币种精度、后端校验及交易状态。BigNumber 不能修复此前已发生的 Number 精度损失；前端防抖和按钮禁用不能保证交易幂等。

## AI 开发方式

每项要求候选人给近期真实例子：

1. 一项交付使用了什么工具、给了哪些需求/代码/约束、得到了什么产物、自己修改和验证什么。
2. 从零做项目时如何明确用户、验收、界面状态、数据与接口边界，先交付可运行的完整功能，再迭代。
3. AI 输出不满意时如何区分需求、上下文、方案、代码缺陷和视觉问题，用日志、复现、截图或针对性检查定位，而不是无休止改提示词。
4. 可复用工作流的输入、步骤、适用条件、质量检查和停止条件；举一次根据失败修订规则的经历。
5. 最近试过的新能力、信息来源、亲自比较的结果、适用场景与限制；不要求追逐最新品牌名。
6. 工作之外的 AI 应用与核实方式；不以使用数量和付费工具数量评分。

重点能力是把问题转成可验收要求、提供有效上下文、审查代码与界面、定位错误、设计验证、控制权限与成本、持续维护和协作。能承认暂时不懂并主动查证有价值；“全部交给 AI”不能替代解释和验证产物。
